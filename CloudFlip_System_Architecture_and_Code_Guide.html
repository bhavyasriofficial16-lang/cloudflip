2. Where the Mathematics Lives in the Code

Formula 1: Exponential Moving Average (EMA)

File: backend/app/ml/prediction/engine.py • _exponential_smoothing(series, alpha=0.35)

def _exponential_smoothing(series: list[float], alpha: float = 0.35) -> float:
    level = series[0]
    for x in series[1:]:
        level = alpha * x + (1.0 - alpha) * level
    return float(level)
Interview Takeaway: "We pass incoming request-per-minute (RPM) readings through single exponential smoothing with α = 0.35. This assigns 35% weight to recent observations and 65% to historical inertia, eliminating micro-burst jitter without lagging behind genuine traffic trends."

Formulas 2 & 3: Velocity Slope & Horizon Demand Projection

File: backend/app/ml/prediction/engine.py • _trend_rate() & forecast()

def _trend_rate(series: list[float], step_minutes: float = 1.0) -> float:
    if len(series) < 2:
        return 0.0
    return (series[-1] - series[0]) / (float(len(series) - 1) * step_minutes)

def forecast(history: list[float], horizon_minutes: float = 15.0) -> float:
    level = _exponential_smoothing(history, alpha=0.35)
    rate_per_min = _trend_rate(history[-5:], step_minutes=1.0)
    # Proactive projection: y(t+H) = L_t + rate * H
    return float(max(0.0, level + rate_per_min * horizon_minutes))
Interview Takeaway: "Because cloud VMs take 3 to 5 minutes to boot, scaling reactively leaves an unmitigated 5-to-8 minute saturation blackout. We compute the first-derivative velocity slope over recent traffic and project demand 15 to 30 minutes into the future to pre-warm instances."

Formula 4: Target Fleet Sizing & Little's Law

File: backend/app/ml/capacity/engine.py • required_capacity()

def required_capacity(predicted_demand_rpm, current_instances, measured_rpm_per_instance):
    current_capacity = current_instances * measured_rpm_per_instance
    target_instances = math.ceil(predicted_demand_rpm / max(1.0, measured_rpm_per_instance))
    required_instances = max(current_instances, target_instances)
    return CapacityPlan(
        current_capacity_rpm=current_capacity,
        predicted_demand_rpm=predicted_demand_rpm,
        required_instances=required_instances,
        additional_instances=max(0, required_instances - current_instances)
    )
Interview Takeaway: "Under Little’s Law (L = λW), when arrival rate λ multiplies during a surge, concurrency L expands. We divide projected demand by per-instance capacity limit (C_inst) using ceiling division to determine exact node count and prevent queue backlog."

3. The Autonomous Agent: 5 Safety Guardrails

File: backend/app/actions/autonomous_agent.py • run_autonomous_remediation_sweep()

To prevent chaotic behavior or runaway cloud expenditures, the agent enforces five hard constraints:

  1. Confidence Score Gate: Aborts autonomous execution if model confidence is < 0.80.
  2. Cost Impact Ceiling: Blocks any scale action that increases burn rate by > $500/hour without human operator confirmation.
  3. Anti-Thrashing Cooldown: Enforces COOLDOWN_SECONDS = 300 (5 minutes) between scaling actions to prevent oscillation (flapping).
  4. Blast-Radius Clamps: Restricts single-step scaling to MAX_SCALE_FACTOR = 3.0, with absolute clamps HARD_MIN = 4 and HARD_MAX = 120.
  5. Autonomy Modes: Supports full_autonomous, semi_autonomous (recommendations only), and off.

4. Closed-Loop Verification: "Don't Trust the API"

File: backend/app/verification/engine.py • verify_scale_action()

def verify_scale_action(cpu_before, cpu_after, latency_before, latency_after, error_before, error_after):
    cpu_improved = cpu_after < cpu_before * 0.85
    latency_improved = latency_after < latency_before * 0.85
    errors_improved = error_after <= error_before
    improvements = sum([cpu_improved, latency_improved, errors_improved])
    
    if improvements == 3:
        return "SUCCESS"
    elif improvements >= 1:
        return "PARTIAL"
    elif cpu_after >= cpu_before and latency_after >= latency_before:
        return "NO_IMPROVEMENT" # Performance regression detected!
    return "UNKNOWN"
The Core Philosophy: "An action is never marked complete just because the cloud provider returned HTTP 200. We measure actual CPU and tail latency before vs. after. If metrics fail to improve by 15%, we flag a regression alert."

"Instead of running heavy deep-learning models like LSTMs that add seconds of inference latency and require massive retraining pipelines, I built an agile, streaming statistical forecaster using EMA smoothing and first-derivative velocity slope. "How does the system ensure safety?" "Through closed-loop control with 5 strict guardrails: an 80% confidence score floor, an hourly cost ceiling ($500/hr), a 5-minute anti-thrashing cooldown, a hard blast-radius clamp (4 to 120 nodes), and a verification engine that measures latency before and after every scaling decision."
